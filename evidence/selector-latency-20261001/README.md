# Candidate latency and calendar-scope repair

A sentence-ending full stop can lower an unused joint parser head below the acceptance threshold even when both learned parsers agree on a correct two-period read plan with high decision confidence. The checker then hands the request to the native model. The local exact question completed in 15–20 seconds before this candidate, including the additional model planning call.

This candidate reevaluates an eligible terminal full stop only after at least two original parser plans agree and their original decision confidence clears the unchanged cutoff. The normalized input must pass the existing acceptance policy and preserve the exact plan. Dates, dotted initials, capitalized final tokens and ellipses are unchanged. Safety handoffs, parser disagreement and explicit checker vetoes remain. The original request hash and subsequent contract, inventory and budget validation remain authoritative. No thresholds or learned weights change.

On the first day of a current week/month, its dates can coincide with today. The decoder now retains the requested period shape and the ordinary period metric date basis instead of narrowing the presentation to today or applying a one-night sleep basis.

Multi-read plans with response-format requirements still need native composition. The attested selector exposes a boolean advisory presentation decision; the local Vita adapter defaults to composition for older builds that lack it. Direct findings still require current settled reads, complete coverage, bound source identities and final authority revalidation. Missing data is not zero-filled.

Local validation: 2,961 implementation tests passed, seven skipped. A 136-case synthetic development regression accepted 68 correct plans, rejected all 40 required handoffs, and had zero runtime or binding errors. This is development evidence, not a new blind evaluation. All 300 existing release-parity outputs remain unchanged; only their reviewed source identity pin changes. The Linux build and pinned live acceptance remain separate gates.

Scope: publish only to the Open-JEV candidate enclave and update only the local Vita rig candidate pins. Production and staging service pins are outside this change.
